C keeps the correctness spine but adds a benchmark-only GPU write lab that cannot become authoritative.

C-01 Ingress

Known templates, hot keys, or deterministic conflict classes may enter the lab lane.

Candidate C Thesis and Owner Topology.

C-02 Admission

vector_credit_admission Adds write-template slots, GPU preprocessing slots, WAL slots, mutation-owner drain budget, and invalidation/refresh budget.

Candidate C Scheduling And Admission Model.

C-03 Mutation Owner

wal_before_visibility The mutation owner still owns WAL reservation, commit order, MVCC apply, invalidation, and final visibility.

Candidate C Owner Topology.

C-04 Visibility

Outputs become SQL-visible only after WAL durability and CPU/MVCC apply.

Candidate C Data Movement and Visibility Model.

C-05 Write Lab

deterministic_hot_write_templatesgpu_oltp_conflict_ordering Benchmark-only preprocessing lane for aggressive write research.

Candidate C Mechanism Set.

C-06 Speculative Boundary

GPU write state has no external visibility boundary and is ignored by crash recovery unless bound to durable commit evidence.

Candidate C Visibility and Recovery Model.

C-07 Retained Reads

Reads use Candidate A retained snapshots and fallback rules after durable invalidation.

Candidate C Visibility Model.

C-08 Lab Gates

Final dossier Fallback Architecture Rules; proof: benchmark-deterministic_hot_write_templates or benchmark-gpu_oltp_conflict_ordering.

Candidate E - Runtime-First 1M-Session Architecture

E is the runtime substrate: prove bounded active-flow cost before broad GPU scope.

E-01 Logical Sessions

One million logical sessions are compact state records, not one hot thread, queue slot, or large allocation each.

Candidate E Owner Topology and Non-Claims.

E-02 Active Flows

effective_session_counting Hot resources are driven by active flows, not logical session count.

Candidate E Scheduling And Admission Model.

E-03 Vector Credits

vector_credit_admission Credits cover request bytes, response bytes, WAL slots, GPU slots, pinned buffers, and response-blocked sessions.

Candidate E Scheduling And Admission Model.

E-04 Owner Rings

owner_ring_bundlingdeficit_fairness Rings batch naturally but expose selected/skipped reasons and protect interactive/tenant classes.

Candidate E Runtime Core.

E-05 Simple Routes

Initial routes can be CPU execution, retained read if already valid and beneficial, reject, wait, or retry.

Candidate E Route And Fallback Model.

E-06 Narrow Retained GPU

retained_gpu_snapshots Optional staged retained snapshots are valid only if they use Candidate A's visibility model.

Candidate E Data Movement and Visibility Model.

E-07 Response Pressure

Response-blocked sessions must consume explicit credits so queues cannot hide behind logical-session counts.

Candidate E Scheduling And Admission Model.

E-08 Runtime Gates

E is proven by vector-credit admission, effective-session counting, owner rings, deficit fairness, microbatch caps, CPU fallback, and isolation trace gates.

Candidate E Validation Model; final dossier Prioritized Proof Plan priority 2.
